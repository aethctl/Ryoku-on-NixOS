UNSTABLE // CURRENT DEVELOPMENT BRANCH

RYOKU ON NIXOS
0.70.2

UNSTABLE BRANCH
BETA.19

This is a major parity and stability update for the unstable branch of Ryoku on NixOS. It brings the NixOS port substantially closer to current upstream Ryoku, expands Niri support, moves more desktop behaviour behind Ryoku's compositor-neutral WM provider layer, and improves how generated compositor configuration follows the active NixOS generation.

✨

New and expanded

  • Major Niri 26.04 parity work. Niri now uses the current split configuration model for input, layout, rules, miscellaneous settings and persisted state instead of relying on one monolithic generator.
  • Expanded compositor-neutral WM provider. Touchpad controls, window summon, output cycling, output enable/disable, Game Mode, Night Light and palette border updates now travel through Ryoku's shared WM seam instead of Hyprland-specific helper paths.
  • Provider-driven Settings pages. Animations, performance, window rules, layer rules, import and other compositor-facing controls now follow the active WM provider and its advertised capabilities.
  • Unified keybind catalogue. Settings and the shell cheatsheet now read the live provider's keybind inventory instead of parsing Hyprland configuration directly. Hyprland and Niri can both report real shortcuts, unsupported actions, rebinds, custom shortcuts and provider-specific behaviour.
  • Palette-following borders. Borders can now dynamically follow the active Ryoku colour palette while still supporting manually pinned colours. This works across both Hyprland and Niri.
  • Numpad parity. Workspace and custom bindings now account for both NumLock-on and NumLock-off keypad keysyms so shortcuts remain functional in either state.
  • Neutral shell helpers. A large group of desktop helpers has moved out of the Hyprland-specific tree and into Ryoku's shared shell payload, including brightness, calculator, colour picker, OCR, QR, recording, radio, song recognition, LocalSend, application launching and system-information helpers.
🛠️

Fixed

  • Niri session handoff. Ryoku now stops its session when the Wayland compositor exits instead of leaving background services attached to a dead Wayland socket after logout.
  • Ryogami NVIDIA crash path. Ryoku shell services now avoid the problematic Qt FFmpeg hardware decoding path that could crash Quickshell through NVIDIA VA-API/CUDA surface export while using Ryogami.
  • Chroma workspace presentation. The Chroma workspace rail has been restored to the intended dot/circle design and once again reacts correctly to live workspace state.
  • Chroma per-display overrides. Individual displays now use a proper Follow global / On / Off model instead of an explicit boolean silently overriding the global shell setting.
  • Brightness persistence. Ryoku now persists the intended brightness setting rather than using the panel's nonlinear raw readback value.
  • Backlight device selection. Internal-panel brightness now uses the appropriate hardware backlight selector.
  • Smarter DDC handling. Ryoku avoids unnecessary DDC probing when no external DRM display is connected and caches I²C bus discovery against the connected monitor set.
  • Settings null handling. Literal JSON null values are guarded correctly rather than leaking invalid state into settings maps.
  • Hyprland native maximize. Maximize behaviour now uses current Hyprland-native functionality instead of the retired fullscreen workaround.
  • Animation preset safety. Snap/base curve handling was corrected so animation presets cannot reference a curve that does not exist.
  • Launcher frost stability. Screencopy capture lifetime is preserved correctly so launcher dismissal cannot destroy capture objects too early.
  • Wallpaper reveal shader. Synced the upstream fix for reveal artefacts.
🖥️

Niri

  • Expanded output management. Ryoku can cycle outputs, enable outputs and move windows or workspaces between outputs through the provider layer.
  • Touchpad state. Touchpad enable/disable state is persisted through the Niri provider and regenerated into the effective configuration.
  • Rules and layout parity. Expanded input, layout, window-rule and configuration generation is now provided by the split Niri backend.
  • Provider window rules. Niri advertises the rule actions it actually supports so Settings does not present controls the compositor cannot honour.
  • Removed obsolete Super-tap handling. The old standalone Super-key tap path has been removed now that the provider-driven desktop no longer depends on it.
  • Current Niri configuration syntax. Generated configuration has been updated for the current Niri 26.04 behaviour and was validated with niri validate.
⌨️

Keybindings

  • One catalogue for both compositors. Ryoku now owns a compositor-neutral keybind catalogue shared by Settings, the shell cheatsheet and WM providers.
  • Live provider inventory. The Keybinds page now reflects the compositor actually running rather than assuming Hyprland's binds.lua is the source of truth.
  • Rebinds remain understandable. Providers expose both the shipped default chord and the effective rebound chord so Settings can display and reset shortcuts correctly.
  • Unsupported binds are visible. When a compositor cannot express one of Ryoku's catalogue actions, the provider reports that limitation instead of silently dropping the shortcut.
  • Custom shortcuts remain supported. User-defined shortcuts are folded into the same provider-driven inventory alongside Ryoku's shipped binds.
🎨

Settings and appearance

  • Provider-aware Settings search. The Window Manager page no longer hard-codes compositor names. Search learns the active provider dynamically.
  • Capability-gated controls. Features such as output mirroring, touchpad controls and window-rule actions are shown only when the active provider says it supports them.
  • Palette-following borders. When enabled, wallpaper/theme palette changes update compositor border colours automatically.
  • Pinned border colours remain respected. Disabling palette-following preserves the user's explicitly chosen border instead of allowing later palette changes to overwrite it.
  • Provider-driven Hub pages. Several compositor-facing Settings pages have been separated from Hyprland assumptions so the same UI works correctly under Niri.
🌙

Night Light

  • Night Light now uses Ryoku's WM capability/action layer instead of having the shell directly assume one compositor backend.
  • Hyprland continues to use hyprsunset.
  • Niri uses the appropriate Wayland gamma backend.
  • The shell discovers the active backend from provider capabilities and presents a common interface to both compositors.
❄️

NixOS integration

  • Generated compositor config now follows the NixOS generation. Ryoku re-authors the effective configuration for both ryoku-wm-hyprland and ryoku-wm-niri from desktop.json during materialization.
  • Provider-side config-generation fixes therefore take effect as soon as the new NixOS generation is switched rather than waiting for the user to save a setting later.
  • Both compositor trees stay current. Even the compositor that is not currently active gets its generated configuration refreshed, preventing a later switch from reviving stale settings.lua, rebinds.lua, settings.kdl or rebinds.kdl.
  • Nix-safe helper packaging. Shared shell helpers use Nix-patched interpreters instead of depending on FHS paths such as /bin/bash.
  • Non-FHS tests corrected. Helper tests that previously replaced PATH with /usr/bin:/bin now preserve the NixOS environment.
  • WM vendor tree. The NixOS packages now build against the real vendored WM seam, with consistency checks ensuring every bundled copy matches ryoku/wm.
🧹

Internal cleanup

  • Multiple compositor-specific helper scripts have been removed or relocated now that their behaviour belongs to the shared WM or shell layers.
  • Game Mode is now dispatched through ryoku wm act decoration.gameMode rather than the shell directly driving Hyprland.
  • The stale Game Mode test was corrected to validate the new WM seam instead of expecting the old direct hyprctl path.
  • Shared WM vendor copies used by the CLI, Hub, Rashin, shell and Ryogami are kept aligned with the canonical implementation.
✅

Validation

  • This update was validated on an actual switched NixOS generation, not only from the source tree.
  • Runtime-tested areas include the Niri provider and generated configuration, Hyprland provider behaviour, Settings / Hub, Keybinds, Window Manager pages, Chroma, palette borders, Night Light, shell helpers and Nix materialization.
  • The generated Niri configuration passed niri validate.
  • WM provider, Hub backend, border policy, JavaScript keybind, vendoring and Nix integration checks passed during the port.
⬆️

Branch and update notes

  • This release is for the unstable branch. It is the current development build of Ryoku on NixOS and is not the stable channel release.
  • Version: 0.70.2-beta.19.
  • Users already tracking unstable can update normally with ryoku update.
  • NixOS generation rollback remains available if a future unstable build causes problems.

ONOGORO
0.66.3

NIXOS PATCH
BETA.19

This update focuses on polishing the NixOS experience, expanding display controls, improving desktop responsiveness, and making Ryoku's update system properly Nix-native.

✨

New

  • Stable and unstable update channels. Ryoku on NixOS can now switch between release and development channels with ryoku track stable and ryoku track unstable. The selected channel is persisted directly in the system's Nix flake configuration.
  • Commit-aware unstable updates. The unstable channel now follows new Ryoku commits even when the visible version number has not changed, so development updates no longer require a version bump before ryoku update can detect them.
  • Per-display shell controls. Ryoku shell visibility can now be configured independently for each display, with bars and shell components enabled or disabled per monitor while retaining sensible global fallbacks.
  • Expanded Chroma controls. Chroma gains additional display and appearance controls, including per-output configuration and more flexible bar presentation.
🛠️

Fixed

  • Hyprland focus-change stutter. Fixed severe desktop stuttering that could occur when moving the pointer between different Hyprland windows while focus-follows-mouse was enabled. Active-window events no longer force unnecessary full compositor state refreshes, and unchanged window-manager state is no longer repeatedly republished.
  • Correct NixOS branding. Ryoku Settings now identifies the platform as RYOKU NIXOS instead of carrying over stale RYOKU ARCH branding. Additional active Arch-specific branding has also been cleaned up.
  • Correct NixOS package statistics. The Profile page no longer presents Arch-specific package terminology and now uses the NixOS-appropriate SYSTEM · USER · TOTAL labels.
  • NixOS Information integration. The dedicated NixOS Information section in Settings has been restored and correctly integrated into the current Hub interface.
  • Stale DDC helper packaging. Removed an obsolete Nix package reference to the old ryoku-ddc-monitors helper. Monitor brightness and DDC/CI support continue through Ryoku's current display services and brightness controls.
⚙️

Improved

  • Safer NixOS updates. Ryoku's Nix update path now builds the complete NixOS configuration before switching generations. If a channel switch fails to build, Ryoku restores the previous flake configuration and lock file instead of leaving the system partially switched.
  • Native Nix update workflow. Ryoku updates on NixOS now operate through the configured Ryoku flake input, with declarative channel selection, flake-input-only updates, pre-switch builds, generation-based rollback, automatic Ryoku service refresh and clear channel/source reporting through ryoku status.
  • Display-state performance. Compositor state handling now refreshes only the window-manager state affected by an event instead of unnecessarily rebuilding unrelated state, substantially reducing shell overhead during frequent focus changes.
  • Documentation and project presentation. The polished Ryoku on NixOS README and artwork have been restored, including the monochrome/editorial project presentation and updated NixOS-specific documentation.
⬆️

Update

  • Users already tracking Ryoku can update normally with ryoku update.
  • To follow development builds, use ryoku track unstable.
  • To return to the stable release channel, use ryoku track stable.
  • NixOS updates continue to use normal NixOS generations for rollback.
ARCHIVE // MUSUBI

MUSUBI
0.63.1

結び
BETA.19

This update brings Ryoku on NixOS up to v0.63.1-beta.19, completing the latest upstream sync while preserving the NixOS-specific adaptations required to keep Ryoku fully declarative and functional. This is a much larger update than the previous patch, with major changes to wallpaper effects, audio, translations, Ryotunes, RyoStore, Ryoku Settings and several parts of the desktop.

✨

Features added

  • Added Ryostage, Ryoku's new wallpaper staging system which replaces the old Depth and Parallax systems.
  • Added support for both Ryostage segmentation models:
    • U2NetP — smaller and faster model for quicker processing.
    • BiRefNet General Lite — much larger model for higher quality cutouts.
  • Added the new 10-band Ryoku Equalizer, including support for EQ presets, individual band controls, enabling/disabling the EQ and automatic audio sink retargeting.
  • Added a fully declarative Ryoku EQ systemd user service for NixOS.
  • Added Ryoku's new shared internationalisation system, including the full upstream translation catalogue and language metadata.
  • Added the new ryoku-i18n tooling to NixOS while keeping all translation data inside the immutable Nix store.
  • Added the new upstream Stage controls and editor, including wallpaper foreground layers, positioning, angles, outlines and Stage widgets.
  • Added the latest upstream Ryoku Settings / Hub changes, including improvements to plugins, profile information, updates and translated UI elements.
  • Added the latest RyoStore backend and interface changes.
  • Added the latest Ryoport interface and backend changes.
  • Added the latest upstream Hyprland integration changes, including updated workspace, keybind and window-rule behaviour.
  • Updated Ryotunes to v1.0.6, replacing the previous legacy v2.5.1 build and bringing the latest native QML client, daemon, CLI and playback changes to Ryoku on NixOS.
  • Added the latest upstream Ryotunes integration used by the Ryoku CLI and Doctor.
  • Added the latest upstream Doctor checks including Stage, language and other new system reconciliation logic while retaining the NixOS-specific Doctor backend.
🛠️

Bug Fixes

  • Fixed Ryotunes packaging for the new v1 release layout.
  • Fixed the Ryotunes native QML client runtime path on NixOS while retaining the declarative ryotunesd service.
  • Fixed Ryotunes launching normal desktop helpers from its daemon by exposing the required NixOS runtime environment without reverting to mutable Arch-style paths.
  • Fixed shared translations not having a stable system-wide location on NixOS by exposing the immutable catalogue through RYOKU_I18N_DIR.
  • Fixed the Ryoku CLI not automatically seeing the new shared translation catalogue.
  • Fixed the shell, Hub and other Ryoku components not having a common NixOS translation path.
  • Fixed Ryostage's upstream mutable Python/venv installation model for NixOS. Required Python libraries are now supplied declaratively instead.
  • Fixed Ryostage model discovery on NixOS while retaining compatibility with existing Depth/Parallax model caches.
  • Fixed the new equalizer relying on Arch system paths by providing the required PipeWire, PulseAudio, systemd and helper tools through its Nix runtime.
  • Preserved the NixOS-specific Docker/Stash behaviour while updating it to the new translated upstream UI.
  • Preserved all existing NixOS-specific CLI, updater, Doctor, Ryogami, Ryotunes and system integration behaviour during the upstream rebase.
  • Fixed remaining references to the old neur0map Ryoku repositories following the upstream move to Ryoku-dev.
  • Synced previously missed lockscreen and shared UI changes discovered during the final upstream integrity audit.
🧹

Changes

  • Depth and Parallax have been retired upstream and replaced by Ryostage.
  • ryoku-depth has been removed and the old Parallax engine has transitioned to the new ryostage command.
  • awww has been removed from the Ryoku Nix runtime. Wallpaper rendering and transitions are now handled by Ryogami.
  • Ryostage model installation is declarative on NixOS. The upstream command is still supported, but NixOS does not create a mutable Python environment behind the user's back.
  • Equalizer startup is managed declaratively through NixOS rather than installing the upstream /usr/bin/pipewire systemd unit.
  • Translation catalogues now live in the shared ryoku/i18n tree instead of the older ryoku/ui/translations layout.
  • Ryoku on NixOS now tracks the new Ryoku-dev organisation for Ryoku and Ryotunes. Unrelated upstream repositories such as neur0map/glazepkg remain unchanged.
  • Ryotunes is now pinned to the exact v1.0.6 source used alongside this Ryoku release rather than following a moving latest version.
  • The old separate ryotunes-qml.desktop launcher has been removed in line with upstream Ryotunes. The standard Ryotunes launcher is now the canonical application entry.
  • RyoStore, Ryoport, Hyprland, the lockscreen and shared Ryoku UI have all been synchronised against the exact v0.63.1-beta.19 upstream source.

0.60.1
BETA.19

RYOKU ON NIXOS
UPDATE PATCH NOTES

This update brings Ryoku on NixOS up to v0.60.1-beta.19, adding the latest upstream features while fixing several NixOS-specific issues found during testing/ bug reporting.

✨

Features added

  • Parallax Wallpapers with layered foreground/background effects and multi-monitor support
  • Parallax tab added beside Depth in Quick Settings
  • KDE colour integration allowing KDE apps to follow Ryoku/Matugen themes
  • Music visualizers now automatically update colours with your wallpaper
  • Improved visualizer rotation and edge positioning
  • Improved HDMI/TV monitor persistence
  • Power profiles now persist more reliably between sessions
  • Ghostty now keeps your personal configuration when Ryoku updates its theme
  • Full visible shell/widget parity with the latest upstream Ryoku
🛠️

Bug Fixes

  • Fixed Ryogami wallpaper UI failing to open on NixOS
  • Fixed Qt/QuickShell incompatibilities which could break wallpaper previews and multimedia features
  • Fixed Parallax not appearing automatically for users upgrading from older Ryoku versions
  • Fixed HDMI displays and TVs losing saved monitor settings after connector changes
  • Fixed wallpaper/theme changes not updating the now-playing spectrum correctly
  • Fixed Ghostty theme updates overwriting user settings
  • Fixed power profile state being lost unexpectedly
  • Removed outdated Spotify/Spicetify integration and leftover packaging
  • Fixed several NixOS packaging, service and dependency issues discovered during the 0.60 port
🧹

Changes

  • Spotify and Spicetify are no longer bundled or managed by Ryoku
  • Ryoku's Qt and QuickShell components are now kept on the same locked version to prevent compatibility issues
⁉️

Known Issues

  • Ryotunes Spotify doesnt work as intended (This song is not avaliable on spotify errors on every song), this is not a bug with NixOS and simply an upstream bug from the main repo
